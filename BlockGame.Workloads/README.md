# Version 1 CPU inputs

`WorkloadCatalog` is the shared definition used by correctness tests and BenchmarkDotNet. Changing an input or semantic expectation requires a version bump. Engine defaults are not consulted for seed, node tree or map bounds. All LODs are zero. Names resolve through app-local production content; registry fallback is rejected.

Meshes use all 27 chunks (center plus 26 neighbors). Synthetic neighbors are null-storage air except `occluded-solid`, where every block is stone. Center inputs are null air, allocated air, full stone, lower-half stone, even-parity checkerboard stone, or frozen terrain. Expected faces are respectively 0, 0, 1536, 0, 1024, 12288 and a nonempty frozen surface. Pools are warmed by one build/dispose before timing, using the provider's delegated resources; each operation includes returning buffers.

`FrozenTerrain.json` contains run-length pairs `(name index, count)` in x-major block order for a 3³ neighborhood generated with seed 1 around source chunk `(0,-58,0)`. Source coordinates are translated by `(0,58,0)` for local meshing; stored neighbor coordinates are -1..1 on each axis. The embedded header records node tree, native SHA-256 and generating feature set. It is a frozen input, never regenerated in benchmark setup. Review its mesh invariants/fingerprint before replacing it; regeneration is a workload change. Tests use predictable face counts, materials, triangle winding, AO and diagonal cases as independent oracles, rather than trusting a hash alone.

Terrain uses seeds 1/42, map size 100, air `(0,64,0)`, solid `(0,-64,0)`, outside `(101,0,0)`, and validated mixed grass-bearing surface chunks `(0,-58,0)` / `(0,-49,0)` respectively. Noise uses the corresponding surface origins, a 16×17×16 grid and step 1, including its output array allocation. Native fingerprints apply only to the recorded DLL/ISA; cross-ISA bitwise equality is not assumed.

Selection measures only `ChunkSelection.Calculate`, including its new HashSet: zero radii at origin; horizontal 0 / vertical 3 at `(-4,-2,3)`; radii 1/1 at that negative center; radii 20/15 at `(12,6,-8)`. It excludes requestor events, task coalescing, unload/reset, scheduler and GPU work.

`SelectionMovementWorkload` defines a separate v1 contract: closed paths from `(-4,-2,3)` with radii 20/15. Cases cover unchanged targets, one X step, a 3-axis diagonal step, a vertical step, teleport, resize to 24/18, and eight successive moves plus return. Every normal path has two transitions; burst has nine. Setup warms retained state and paths finish at their initial set. `ScenarioContracts` serializes every target and radius, independently of algorithm/revision identity. The historical `SelectionReference` is a double-precision model; it does not reproduce the actual float/preallocated implementation at c2a6ab2 and cannot serve as a revision baseline. It remains a test/calibration model only. Use clean Git revision builds via the short worker guide.
